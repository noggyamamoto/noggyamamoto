<h2>🚀 Projetos em Destaque</h2>

<h3>💳 <a href="https://github.com/noggyamamoto/BRICS_Payment">BRICS_Payment</a> — Sistema de Pagamentos e Investimentos</h3>
<p>Projeto de CRUD com tratamento DevOps que visa uma plataforma financeira comum do bloco econômico BRICS rumo à desdolarização. Inclui <strong>frontend web responsivo</strong>, <strong>backend com API REST</strong>, autenticação via <strong>JWT</strong>, operações bancárias (depósito, saque, transferência), consulta de extrato, gestão de investimentos e validações de regras de negócio (saldo insuficiente, unicidade de CPF/e-mail, limites de saque).</p>

<h3>🔐 <a href="https://github.com/noggyamamoto/JavaSecurityApplication">SecurityApplication</a> — Demonstração de Session Hijacking</h3>
<p>Aplicação <strong>Spring Boot</strong> que expõe intencionalmente vulnerabilidades de <strong>gestão de sessão</strong> para demonstrar ataques de <strong>Session Hijacking</strong>. O cenário mostra como um atacante pode roubar o cookie de sessão de uma vítima via <strong>XSS armazenado</strong> e assumir sua identidade. Em seguida, o código é fortalecido com flags de cookies seguros (<code>HttpOnly</code>, <code>Secure</code>, <code>SameSite</code>) e <strong>regeneração do ID de sessão</strong> no login, conforme recomendações da <strong>OWASP</strong>.</p>

<h3>⚙️ <a href="https://github.com/noggyamamoto/JavaSpringApplication">SecurityApplication</a> — Demonstração de Mass Assignment</h3>
<p>API REST em <strong>Spring Boot</strong> que demonstra a vulnerabilidade de <strong>Mass Assignment</strong>. O projeto expõe um endpoint <strong>vulnerável</strong> (binding direto de JSON para entidade JPA) e um endpoint <strong>seguro</strong> que mitiga a falha com <strong>DTO e allowlist explícita</strong>, permitindo comparar as abordagens na prática.</p>

<h3>🎮 <a href="https://github.com/noggyamamoto/ProjetoFlappyBird">Flappy Bird</a> - Desenvolvimento do Jogo</h3>
<p>Jogo clássico recriado em <strong>Java</strong> com a biblioteca <code>javax.swing</code>. O projeto aplica conceitos de <strong>programação orientada a objetos</strong>, controle de colisões, geração procedural de obstáculos e pontuação progressiva, desenvolvido como prática dos conteúdos da faculdade.</p>

<h3>🍢 <a href="https://github.com/noggyamamoto/EspetinhoMaria">Espetinho da Maria</a> — Sistema de Gestão de Pedidos</h3>
<p>Sistema completo de gestão de pedidos para o <strong>Espetinho Maria</strong>, desenvolvido com <strong>arquitetura MVC</strong> utilizando <strong>Node.js, Express.js e SQLite</strong>. Oferece <strong>painel administrativo</strong> com CRUD de produtos, <strong>controle de estoque em tempo real</strong>, gerenciamento de pedidos com status e histórico, <strong>dashboard com estatísticas de vendas e faturamento</strong>, e <strong>autenticação segura baseada em cookies HTTP-only</strong>. A interface do cliente é responsiva e intuitiva, com visualização do cardápio e contato direto via WhatsApp. O backend expõe uma <strong>API REST padronizada</strong> (produtos, categorias, estoque, pedidos) e o banco SQLite é criado automaticamente na primeira execução, sem dependências externas.</p>

<h3>🌱 <a href="https://github.com/noggyamamoto/SMAVHIoT">SMAVHIoT</a> — Monitoramento para Agricultura Vertical Hidropônica</h3>
<p>Sistema completo de monitoramento IoT com <strong>Raspberry Pi</strong>, sensores de temperatura/umidade, luminosidade e display <strong>OLED</strong>. Os dados são publicados via <strong>MQTT</strong> para brokers na nuvem, com sistema de alertas para valores críticos.</p>

<h3>🎵 <a href="https://github.com/noggyamamoto/firmware_I2S">Firmware_I2S</a> — Dispositivo de Captação, Tratamento e Segmentação de Notas musicais</h3>
<p>Firmware do dispositivo embarcado do TCC <strong>"Sistema de Processamento de Áudio com Feedback em Tempo Real Aplicado ao Ensino de Partitura"</strong>. O dispositivo capta o som de um teclado com microfone digital <strong>INMP441 (I2S)</strong>, filtra os ruídos, estima a frequência fundamental, segmenta as notas identificadas (altura e duração) e envia os eventos ao aplicativo Flutter via <strong>Wi-Fi</strong>, além de executar metrônomo sonoro e visual (buzzer e LED RGB). O app compara as notas recebidas com a partitura MusicXML e devolve o feedback ao aluno.</p>

<h3>📱 <a href="https://github.com/noggyamamoto/Flutter_App">Flutter_App</a> — Aplicativo de Prática de Partitura com Feedback em Tempo Real</h3>
<p>Aplicativo Flutter do mesmo TCC mencionado anteriormente. O aluno toca a partitura exibida no app; o dispositivo embarcado identifica as notas e as envia ao aplicativo, que compara cada nota com a partitura <strong>MusicXML</strong> e mostra o resultado na hora: <strong>verde para acerto</strong>, <strong>amarelo para aproximado</strong> e <strong>vermelho para erro</strong>, no estilo de aplicativos como Simply Piano e Yousician.</p>
